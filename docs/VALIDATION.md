# Validation and boundaries

The app/SDK 0.1.0 and private driver candidate 0.1.0.0 target Windows 10 build 19041+ x64. Target support is not a completed qualification claim. The private candidate passed normal and targeted Driver Verifier campaigns in a Windows 10 build 19045 x64 Hyper-V guest. Microsoft signing remains pending. Public preview archives exclude the unsigned driver and compiled setup executables.

Completed local checks:

- Native app, CLI, example, installer and test targets build with MSVC W4/WX, CFG, ASLR, NX, static CRT and UTF-8 source handling.
- 200,007 ABI mutation/bounds and installer identity/unsigned-signature refusal checks pass normally and with AddressSanitizer. They do not open a driver or change device associations.
- The private KMDF driver builds with W4/WX and PREfast XML zero defects. InfVerif `/w`, `/u` and catalog generation pass.

The exact unsigned SYS SHA-256 `9D4DD9CD78B995F94B7E59DD32E1FF87D964BC834B1B711DC9C283EBD8B002BB` completed **3,175 checks normally and 3,175 with standard Driver Verifier** on 2026-10-25. A temporary guest-only signature allowed testing. The separately Microsoft-signed Vdevice fixture used a unique standalone vendor-defined HID device, with no keyboard/mouse usage or host hardware target. Actual interrupt IN/OUT and HID class-control payloads were observed, with independently verified unchanged host/device data. An IN request deliberately pending before capture produced its sampled completion with the pre-existing flag. The 600-report pressure loop exercised bounded ring overwrite; malformed protocol requests, forged/replayed grants, real expiry, stop and owner cleanup were checked in both runs.

Restricted-token control access, administrator zero/read-only/write-only opens and a second control owner were refused. Both campaigns installed byte-identified copies, restored the exact original filter property, deleted the owned fixture, removed the product and Vdevice/clock packages and verified all services unloaded. No new crash dump was observed. The designated VM returned to its powered-off original baseline with nine historical checkpoints; the host's driver/security settings were not changed. Verifier targeted the candidate and its fixture drivers, not physical host hardware or every Windows USB component.

The fixture's normal PnP restart was tested without USB Trace first and reproduced a real input timeout with configured=false. The test therefore recreated only the owned fixture with the same serial/descriptors after association, verified the exact instance identity and then exercised its freshly configured filtered stack. This is an explicitly recorded Vdevice-fixture limitation, not proof of physical USB restart or reconnect compatibility. The check count includes variable fixture coordination assertions, not thousands of independent hardware configurations.

The live fixture qualified HID class-control and interrupt paths. Bulk uses the implemented shared bulk/interrupt URB parser, but no live WinUSB/bulk workload was qualified. Large bulk transfers, chained-MDL behavior and physical SuperSpeed controllers/devices remain pending rather than implied by this HID result.

The filter always forwards original USB requests unchanged. It does not originate USB transfers, retain them for a user decision or enforce filtering policy on their content. Only bounded diagnostic data is copied. Transfer-buffer reads rely on the documented resident USB URB contract for the kernel-only internal USB major; a reused HID IRP can legitimately retain its original user requestor mode. URB pointers and direct buffers must be kernel addresses; MDLs use safe system mappings with no-execute and bounded byte counts. External user device-control requests never enter the URB parser. Chained MDLs and unavailable/mutated layouts are flagged rather than flattened or assumed valid. No kernel pointer or raw pipe handle is exposed in public records.

Every tracked request holds an ordinary WDF request completion context. Supported requests retain bounded completion metadata even when inactive, without copying inactive payloads. Configuration/interface observations provide a bounded map of endpoint handles to endpoint/type metadata. Stop/close/new-owner generations prevent a request already captured for an older generation from being re-labelled for a later owner. Previously inactive requests may be admitted at an authorized completion with an explicit pre-existing flag; OUT payloads from before capture are never read. Completion admission snapshots the current generation, and publication rechecks permission, module and generation after copying. IN samples are copied only after compatible successful completion; OUT samples describe what was submitted, including when the transfer later fails. Counter/flags explain truncation, unavailable samples, unknown actual length, observation overflow and untracked request pressure.

Microsoft-signed package return tests, Windows 11, Secure Boot/HVCI, physical controllers/devices, composite-device combinations, third-party USB filters, suspend/resume, surprise removal, low-resource simulation and prolonged high-rate workloads remain to be qualified. Isochronous payloads, USB redirection, packet-level electrical analysis and universal device support are not implemented or claimed.

The final CAB was generated from the exact qualified INF/SYS/CAT/PDB files without recompiling the driver; all four members were extracted and byte-verified. A returned Microsoft signature will require a separate installation/runtime/removal campaign.
